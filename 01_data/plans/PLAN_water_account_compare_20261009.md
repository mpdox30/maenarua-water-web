# แผน: ระบบ "บัญชีน้ำอ่างแม่นาเรือ" + ฟังก์ชันเปรียบเทียบ แบบ thaiwater.net/water/dam/large
วันที่: 2026-10-09 · สถานะ: **แผน (ยังไม่เริ่มสร้าง)**

## 1. วิเคราะห์เว็บต้นแบบ (ตรวจจริงเมื่อ 2026-10-09)

**สถาปัตยกรรม** — React SPA (Material-UI + Highcharts) หน้าเว็บไม่มีข้อมูลใน HTML; ดึงจาก API เดียวทั้งหน้า
`GET api-v3.thaiwater.net/api/v1/thaiwater30/analyst/dam` (~885 KB, JSON)

| key ใน `data` | จำนวน | ความหมาย |
|---|---|---|
| `dam_daily` | 50 | เขื่อนใหญ่ กรมชลประทาน รายวัน (storage, %, inflow, inflow_acc, uses_water, released, released_acc, level, spilled ...) |
| `dam_hourly` | 17 | เขื่อน กฟผ. รายชั่วโมง |
| `dam_medium` | 862 | อ่างขนาดกลาง |
| `dam_small_tele` | 60 | อ่างขนาดเล็กที่มีโทรมาตร สสน. (**รวม RES002 อ่างแม่นาเรือ id 1512928**: level 489.905, volume 1.738 ล้าน ลบ.ม., 107.76%) |

พารามิเตอร์เสริม: `?dam_date=YYYY-MM-DD` (+ `&dam_size=`) ใช้ดูย้อนหลังรายวัน

**ตารางหลัก** (จัดกลุ่มตามภาค มีแถวรวมภาค) คอลัมน์:
ความจุอ่าง (ที่ รนก.) → น้ำในอ่าง: กักเก็บ (% ) / ใช้การได้จริง (%) → ปริมาตรน้ำไหลลงอ่าง: รายวัน / สะสมตั้งแต่ 1 ม.ค. (%) / ค่าเฉลี่ยทั้งปี → ปริมาตรน้ำระบาย: รายวัน / สะสมตั้งแต่ 1 ม.ค.
สีตัวเลข % (แดง/น้ำเงิน) บอกระดับน้ำ; ท้ายแถวมีไอคอน 2 ปุ่ม

**ปุ่มไอคอน 2 ปุ่มต่อแถว**
1. กราฟเส้นรายวัน (ตลอดปี) — `analyst/dam_yearly_graph?data_type=<type>&dam_id=<id>&year=<y>` (หลายปี/หลายอ่าง: `dam_yearly_graph_multiple`) ตอบ `graph_data[{year, dam_name, data[{date,value}]}]` + `upper_rule_curve, lower_rule_curve, upper_bound, lower_bound, normal_bound, average_inflow, sum_average_inflow`
2. **กราฟเปรียบเทียบ (ภาพที่ 1–2 ของคุณ)** — แท่ง "วันเดียวกันของทุกปี" (2012–2026) พร้อมตัวควบคุม: ประเภทข้อมูล, อ่างเก็บน้ำ, วัน, เดือน, ปี (เลือกหลายปี), ปุ่ม "แสดง"; มี range-slider ด้านล่าง ซูมได้
   - 7 ประเภทข้อมูล: `dam_storage` (น้ำเก็บกัก), `dam_uses_water` (ใช้การ), `dam_inflow` (ไหลลง), `dam_released` (ระบาย), `dam_inflow_acc` (ไหลเข้าสะสม), `dam_released_acc` (ระบายสะสม), `dam_level` (ระดับน้ำ)
   - ⚠ endpoint ที่ใช้วาดแท่งเทียบวันเดียวกัน **ผมยังไม่ได้จับ request จริง** (คาดว่าคำนวณจาก `dam_yearly_graph` หลายปีฝั่ง client หรือใช้ endpoint ที่ไม่ได้ปรากฏในโค้ด) ต้องจับเพิ่มก่อนลอกพฤติกรรมให้ตรง — แต่ไม่จำเป็นต่อการสร้างของเราเอง เพราะข้อมูลอยู่ในมือเรา

**อ่างเล็ก (รวมแม่นาเรือ)** — `analyst/dam_small_tele_graph?data_type=volume&tele_station_id=<id>&start_date=&end_date=` (กราฟปริมาตรช่วงวันที่)

**ข้อสังเกต/ข้อจำกัดของต้นแบบ**: เป็น API ของ สสน. ไม่มีเอกสารรับรองการใช้งานต่อ → **ไม่ควรให้เว็บเราพึ่ง API นี้ตอนรันจริง**; เรานำแค่ "หน้าตา/รูปแบบการใช้งาน" มาออกแบบ ข้อมูลใช้ของเราเอง

## 3. แผนสร้าง (เป็นเฟส)

**เฟส 1 — ข้อมูล (ฝั่ง pipeline)**
1. สร้าง `assets/data/water_account_series.json` (ไฟล์เดียว แยกจาก `water_ledger.json` เดิมไม่แตะ) โครงสร้างต่อวัน: `date, level_m, storage_m3, storage_pct (÷1.613 ล้าน), inflow_m3, inflow_acc_ytd_m3, release_m3 (O+spill), release_acc_ytd_m3, spill_m3, rain_mm, flags[]`
2. เพิ่มธง `qin_unverified` (11 ก.ย. 2026 เป็นต้นไป ใช้ rating δ=0.17 ชั่วคราว) ให้ UI แสดงเป็นแถบลายขีด/ไอคอนเตือน — **ตัดสินใจแล้ว: ใช้ δ=0.17 ต่อไป**
3. ย้ายการสร้างให้เป็นอัตโนมัติรายวัน (ต่อท้าย `daily_update.py` หรือ bat รายวัน) แทนการรัน manual จากไฟล์ xlsx — ต้องตกลงแหล่งข้อมูลหลัก (ledger xlsx "ฉบับสูตรสปิลเวย์แก้ไข" หรือคำนวณจากระดับน้ำรายวันโดยตรง)
4. (ตัวเลือก) ไฟล์ storage รายวันของอ่างอื่นในพื้นที่ จาก `api_snapshots.csv` + rating curve ต่ออ่าง

**เฟส 2 — หน้าตารางสรุป (เหมือน thaiwater)**
คอลัมน์: ความจุ (รนก.) · กักเก็บ (ล้าน ลบ.ม. / %) · น้ำไหลลง (รายวัน / สะสม 1 ม.ค.) · น้ำระบาย (รายวัน / สะสม 1 ม.ค.); เลือกวันที่ย้อนหลังได้; ปุ่ม 2 ไอคอนท้ายแถว; สี % ตามเกณฑ์ (กำหนดเกณฑ์ของเรา เช่น <30% / 30–80% / >80% / ล้นสปิลเวย์)

**เฟส 3 — ฟังก์ชันเปรียบเทียบ**
- โมดอล "เปรียบเทียบรายวัน": ประเภทข้อมูล 7 แบบเหมือนต้นแบบ (ใช้ชื่อฟิลด์ของเราแมปไว้), เลือก อ่าง / วัน / เดือน / ปี (หลายปี) → กราฟแท่งวันเดียวกันข้ามปี + กราฟเส้นซ้อนปี (แกน x = วันที่ในปี) + เส้นอ้างอิง รนก. และสันสปิลเวย์
- ซูม/แท่งเลื่อนช่วงเวลา, ส่งออก PNG/CSV
- ไลบรารีกราฟ: ต้นแบบใช้ Highcharts (ฟรีเฉพาะไม่แสวงหากำไร ต้องดูสัญญาอนุญาต) → แนะนำ **Chart.js หรือ ECharts** (MIT/Apache) ไม่ต้องกังวลเรื่องสิทธิ์ ใส่เป็นไฟล์เดียวในหน้าได้
- ไม่เพิ่ม dependency ฝั่ง server; ทุกอย่างอ่าน JSON สถิตเหมือนหน้าอื่น

**เฟส 4 — ทดสอบ/ส่งมอบ**
ตรวจตัวเลขกับ `water_ledger.json` (ผลรวม ΔS, สะสม 1 ม.ค.), ทดสอบมือถือ, เทียบภาพกับต้นแบบ, อัปเดต README/วิธีรันอัตโนมัติ

## 4. ความเสี่ยง
- ประวัติสั้น → กราฟเทียบปีดูโล่งในช่วงแรก (ต้องบอกผู้ใช้ชัดเจนบนหน้าเว็บ)
- ตัวเลขน้ำไหลเข้าตั้งแต่ 11 ก.ย. ยังไม่ยืนยัน → ห้ามนำไปคำนวณ "ค่าเฉลี่ยทั้งปี"/สะสมโดยไม่ติดธง
- ตัวเลขสะสม 1 ม.ค. ของปี 2026 ใช้ได้ (ข้อมูลเริ่ม 1 ม.ค. 2026 ครบ) แต่ของ 2025 เริ่มที่ 27 มิ.ย. จึงเทียบ "สะสมทั้งปี" 2025 ไม่ได้
- การใช้ข้อมูล/ภาพของ thaiwater.net: เราลอกเฉพาะรูปแบบการแสดงผล ไม่ดึงข้อมูลจากเขาเข้าเว็บเรา

## 5. ต้องตัดสินใจก่อนเริ่ม
1. ขอบเขต: เฉพาะอ่างแม่นาเรือ หรือรวมอ่างอื่นในพื้นที่ (storage อย่างเดียว) ด้วย
