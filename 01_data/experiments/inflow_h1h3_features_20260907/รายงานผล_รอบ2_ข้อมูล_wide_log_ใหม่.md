# ผลทดลอง range_24h รอบ 2 — ใช้ wide_log ที่อัปโหลดใหม่ (2026-09-07)

สถานะ: **ทดสอบเสร็จแล้วในโฟลเดอร์นี้เท่านั้น ไม่ได้แตะ production**

สรุปสั้น: **ผลสุดท้ายไม่ดีขึ้น ไม่แนะนำ deploy** — สัญญาณบวกที่เห็นตอนแรกไม่ผ่านการทดสอบรอบสุดท้าย
ที่เข้มงวดที่สุด (วิธีเดียวกับที่ใช้ตัดสินใจ deploy โมเดลปัจจุบันไปแล้ว)

## สิ่งที่ทำเพิ่มจากไฟล์ wide_log (3).csv ที่อัปโหลดมา

ไฟล์ใหม่ครอบคลุม **2026-07-10 ถึง 2026-09-07** (7,938 แถว, poll ทุก ~10 นาที) ยาวกว่าฉบับเก่ามาก
รวมกับข้อมูลรายชั่วโมงเดิม ทำให้คำนวณ `max_level_24h`/`range_24h` ได้ครอบคลุม **424/438 วัน**
(ขาดแค่ 2026-06-28 ถึง 2026-07-10, 13 วัน) — **ครอบคลุมเกือบทั้งช่วงของ `forecast_accuracy_log.csv`
แล้ว (27 มิ.ย. – 6 ก.ย.)** ต่างจากรอบก่อนที่ validate กับ log จริงไม่ได้เลย

## ขั้นตอนการทดสอบ (3 รอบ ผลกลับทิศกัน — สำคัญที่สุด)

### รอบ A: เทียบ raw prediction (ไม่มี bias correction) กับ log ทั้งหมด (44-50 แถว)
ดูดีมาก ทุก horizon ดีขึ้น 9-81% — **แต่ baseline ที่ใช้เทียบคือค่า predicted จริงใน log ซึ่งส่วนใหญ่มา
จากโมเดลเก่าก่อนจะแก้ h5/เพิ่ม rain-feature/regularize** ไม่ใช่การเทียบกับระบบที่ deploy อยู่ตอนนี้
เลยดูดีเกินจริง — ไม่ใช่ baseline ที่ถูกต้องสำหรับตัดสินใจ

### รอบ B: apples-to-apples กับโมเดลที่ deploy จริงตอนนี้ (regularized+rain, ไม่มี bias) บน 44-50 แถว

เอาเฉพาะแถว out-of-sample จริง (หลัง 2026-07-24 ซึ่งเป็นวันสุดท้ายของ training data) ก็ยังทิศทาง
เดิม: H2,H4,H5,H6,H7 ดูดีขึ้น, **H3 แย่ลงสม่ำเสมอทุกรอบทดสอบ**, H1 แทบไม่ต่าง

จุดนี้เลยตัดสินใจทำ **"selective candidate"**: ใส่ range เฉพาะ H2,H4,H5,H6,H7 (ไม่ใส่ H1,H3)

### รอบ C (รอบสุดท้าย, เข้มงวดที่สุด): เทียบ deployed+bias เดิม vs selective+bias ใหม่ บน holdout 35%

กับที่ตัดสินใจ deploy โมเดลปัจจุบัน) ผลกลับแย่ลงสุทธิ มีแค่ H6 ที่ดีขึ้นเล็กน้อย (+4.1%)

## ทำไมผลถึงกลับทิศ — บทเรียนซ้ำจาก session นี้

เป็นรูปแบบเดียวกับที่เจอตอนทดสอบ feature ฝนพยากรณ์แบบ continuous: **ผลดูดีตอนใช้ sample ใหญ่/วิธี
วัดที่ยังไม่เข้มงวดพอ (รอบ A, B) แต่พอบีบให้แคบลงเหลือเฉพาะ holdout ที่ไม่เคยใช้ fit อะไรเลยจริงๆ
(รอบ C) ผลไม่เสถียร** สาเหตุน่าจะมาจาก sample size เล็ก (16-18 วันต่อ horizon) รวมกับการ fit bias
correction ซ้อนบน feature ใหม่ ทำให้ noise สูง ไม่ใช่สัญญาณที่เชื่อถือได้พอจะ deploy

## สรุปและคำแนะนำ

**ไม่แนะนำ deploy range_24h/max_level_24h ไม่ว่าจะใส่ทุก horizon หรือใส่แบบเลือกเฉพาะ H2,H4-H7**
เหตุผลหลัก 2 ข้อ:

1. **ไม่ช่วยเป้าหมายหลักเลย** — H1,H3 (2 ใน 3 วันแรกที่ขอให้ลองปรับปรุง) ไม่ได้ feature นี้อยู่ดี (H1
   ผลกลาง H3 แย่ลงทุกรอบทดสอบ) ส่วน H2 เปลี่ยนแทบไม่ถึง 1% — **แปลว่าต่อให้ผล H4-H7 เชื่อถือได้ 100%
   ก็ไม่ตอบโจทย์ที่ขอมา (อยากปรับปรุง 3 วันแรก)**
2. ผลของ H4-H7 เองก็ไม่เสถียรระหว่างวิธีวัด (ดีขึ้นในรอบ B แต่แย่ลงในรอบ C ซึ่งเป็นรอบที่เข้มงวดกว่า
   และใช้วิธีเดียวกับที่ตัดสินใจ deploy จริงไปแล้ว)

นอกจากนี้ยังมีข้อจำกัดเชิงระบบเดิม (ต่อให้ผลดี ก็ยัง deploy จริงไม่ได้ทันที เพราะ telemetry สดยังไม่ได้
เชื่อมเข้า `data_pipeline.py`) แต่ข้อนี้ไม่ใช่เหตุผลหลักในการตัดสินใจรอบนี้แล้ว เพราะผลตัวเลขเองก็ไม่ผ่าน
