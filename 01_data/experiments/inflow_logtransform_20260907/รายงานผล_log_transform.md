# ผลทดลอง signed-log(delta) target transform (2026-09-07)

สถานะ: **ทดสอบเสร็จแล้วในโฟลเดอร์นี้เท่านั้น ไม่ได้แตะ production**

## สรุปสั้น: ไม่แนะนำ deploy — ผลใกล้ 0 ในการทดสอบรอบสุดท้ายที่เข้มงวดที่สุด (ซ้ำรูปแบบเดียวกับ
range_24h)

## วิธีทำ

Tweedie ต้องพยากรณ์ตรงๆ (ไม่ใช่ delta) ซึ่งพิสูจน์แล้วว่าสถาปัตยกรรมแพ้ delta-regression เดิม เลยลอง
**log-transform บน delta แทน** (ไม่เปลี่ยนสถาปัตยกรรมที่ชนะอยู่แล้ว): `signed_log(delta) =
sign(delta) × log1p(|delta|)` แล้ว fit CatBoost (MAE loss, hyperparameter regularized เดิม) พยากรณ์
ค่านี้แทน delta ตรงๆ, invert กลับตอนทำนาย

## สรุปและคำแนะนำ

**ไม่แนะนำ deploy** ด้วยเหตุผลเดียวกับ range_24h: (1) ไม่ช่วย H1-H3 เลย (2) ผล H4-H7 พอผ่านการทดสอบ
รอบสุดท้ายที่เข้มงวดแล้วเหลือแค่ noise-level (~0.2% โดยรวม, H4 กลับแย่ลงด้วยซ้ำ)

## ข้อสังเกตสำคัญ (บทเรียนภาพรวมของ session นี้)

นี่เป็น**ครั้งที่ 3 ติดต่อกัน** (ต่อจาก rain-forecast แบบ continuous และ range_24h) ที่สัญญาณดีจาก CV/
การทดสอบชุดใหญ่ **หายไปเมื่อทดสอบด้วย holdout ท้ายสุดที่เข้มงวดที่สุด (16-18 แถว/horizon)** — สาเหตุ
น่าจะเป็นเพราะ `forecast_accuracy_log.csv` สะสมมาแค่ ~52 วัน ยังมี sample ไม่พอจะเห็นความแตกต่างเล็กๆ
ได้อย่างเชื่อถือได้ **ข้อเสนอ: การปรับปรุงเพิ่มเติมแบบ "ปรับโมเดล/feature/loss เล็กๆ น้อยๆ" บนข้อมูล
ชุดนี้อาจถึงเพดานแล้ว — ทางที่มีโอกาสสำเร็จมากกว่าคือการเพิ่มปริมาณข้อมูล (รอสะสม log เพิ่ม หรือหา
ข้อมูลย้อนหลังเพิ่ม) มากกว่าการลอง technique ใหม่ๆ บนข้อมูลเท่าเดิม**
