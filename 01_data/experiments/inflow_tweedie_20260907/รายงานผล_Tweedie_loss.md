## ทำไมต้องเปลี่ยนสถาปัตยกรรมก่อนถึงจะลอง Tweedie ได้

Tweedie loss กำหนดว่า **target ต้องไม่ติดลบ** แต่สถาปัตยกรรมปัจจุบัน (delta-regression) พยากรณ์ค่า
"ผลต่าง" (y_h − Q_in_t) ซึ่งติดลบได้ปกติ (inflow ลดลงจากวันนี้) เลยใช้ Tweedie ตรงๆ กับของเดิมไม่ได้
ต้องเปลี่ยนมา **พยากรณ์ค่า inflow ในอนาคตตรงๆ** (y_h เอง ซึ่ง ≥ 0 เสมอ) แทน — เป็นการเปลี่ยน
สถาปัตยกรรม ไม่ใช่แค่เปลี่ยน loss function เฉยๆ

## ปัญหาที่เจอระหว่างทดสอบ (สำคัญ เป็นบทเรียนทางเทคนิค)

รอบแรกที่ทดสอบ (ใช้ early-stopping/`od_wait` และ learning rate เดิมที่ tune ไว้สำหรับ delta-regression)
ผลออกมาพังสนิท (NSE ติดลบหนักทุก horizon, prediction เพี้ยนเหลือแค่หลักร้อย-พัน ทั้งที่ actual อยู่ระดับ
แสน) วินิจฉัยแล้วพบสาเหตุ 2 ชั้นซ้อนกัน:

1. **Learning rate เดิมเล็กเกินไป**: Tweedie ใช้ log-link (คูณสะสม ไม่ใช่บวกสะสมแบบ MAE) การพยากรณ์
   ค่าตรงๆ ระดับแสน-ล้าน ต้องการ cumulative log-increment มาก ด้วย learning rate ~0.01 (ที่ tune ไว้
   สำหรับ delta ซึ่งมีขนาดเล็กกว่ามาก) ต้องใช้ต้นไม้เป็นพันต้นกว่าจะถึงสเกลที่ถูกต้อง
2. **Early-stopping ใช้ไม่ได้กับ Tweedie deviance ของข้อมูลนี้**: แม้แก้ learning rate แล้ว
   early-stopping ก็ยังหยุดเร็วเกินไป (บางครั้งแค่ 1 ต้น) เพราะ Tweedie deviance บน eval set เล็กๆ
   (~47 แถว) ไม่ monotonic ในช่วงต้น — ทดสอบแบบไม่ใช้ early-stopping (fixed iterations) แล้วดู
   training curve ตรงๆ พบว่าโมเดลค่อยๆ ลู่เข้าถูกทิศจริง แต่ใช้เวลาหลายสิบ-ร้อยรอบกว่าจะเห็นผล

แก้โดยใช้ fixed iterations (ไม่ early-stop) + learning rate ที่สูงขึ้น (0.1) — ทำให้ได้ผลลัพธ์ที่สมเหตุ
สมผล (ไม่ใช่ prediction เพี้ยนแบบก่อนหน้า) แต่ **ต่อให้แก้ปัญหาทางเทคนิคนี้แล้ว ผลลัพธ์ก็ยังแพ้โมเดล
ปัจจุบันทุก horizon**

## ทำไม Tweedie ถึงแพ้ ทั้งที่ควรเหมาะกับข้อมูลแบบนี้ (zero-inflated, skewed)

Tweedie deviance (p ระหว่าง 1-2) ให้น้ำหนักกับค่าที่ใหญ่มาก (เหตุการณ์ฝนตกหนัก/inflow พุ่งสูง) หนักกว่า
MAE มาก — ทำให้โมเดลไพล่ไปโฟกัสพยายามจับเหตุการณ์สุดขั้วไม่กี่ครั้ง แลกกับความแม่นยำในการพยากรณ์
ค่าทั่วไป (ที่เกิดบ่อยกว่ามาก) ซึ่งเป็นสิ่งที่ MAE (ที่ใช้อยู่ปัจจุบัน) ให้ความสำคัญมากกว่า — สำหรับข้อมูล
ชุดนี้ (393 วัน ยังไม่เยอะมาก) MAE เหมาะกับเป้าหมาย "แม่นยำสม่ำเสมอในกรณีทั่วไป" มากกว่า

## สรุปและคำแนะนำ

**ไม่แนะนำ deploy หรือพัฒนาต่อ** — แพ้โมเดลปัจจุบันทุก horizon อย่างชัดเจน โดยเฉพาะ H1,H2,H3 ที่เป็น
เป้าหมายหลักของรอบนี้ (แพ้มากถึง -0.19 ถึง -0.39 NSE) ไม่จำเป็นต้อง validate กับ log จริงเพิ่มเติม
เพราะช่องว่างจาก CV ใหญ่และสม่ำเสมอทุก horizon (ต่างจากกรณี feature ใหม่ก่อนหน้านี้ที่ CV ดูดีแต่ต้อง
ระวังผล optimistic — กรณีนี้ CV แย่ชัดเจน ซึ่งเป็นสัญญาณที่เชื่อถือได้ในทิศทาง "ไม่ควรลงทุนต่อ")
