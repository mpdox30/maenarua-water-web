## สาเหตุ (ยืนยันจากสูตร water balance ในไฟล์จริง)

RES002 (แม่นาเรือ) มีเหตุการณ์ปล่อยน้ำต่อเนื่อง "event#2" อัตราคงที่ 9,446.4 m3/วัน ตั้งแต่ปลาย มิ.ย.
**ยังไม่ปิด** (ดู `01_data/Reservoirs/release_log/release_events.csv`) สูตร:

```
inflow = ΔStorage + Release + Spill + Evap + Infiltration, floor ที่ 0
```

ตราบใดที่ฝนที่เติม storage เข้ามาน้อยกว่าปริมาณที่ปล่อยออกทุกวัน (9,446 m3/วัน) ΔStorage จะติดลบสุทธิ
เสมอ ทำให้ inflow คำนวณได้ (ก่อน floor) เป็นค่าลบ แล้วถูก floor เหลือ 0 — **นี่คือพฤติกรรมที่ถูกต้องตามนิยาม
ปัจจุบันของ "inflow", ไม่ใช่โมเดลทำนายผิด** แต่ผลคือ "ฐาน" ที่ delta-regression ใช้บวก/ลบต่อ (Q_in_t
ปัจจุบัน) แบนที่ 0 มาตลอด 2 สัปดาห์ ทำให้ผลทำนายทุก horizon ดูไม่ขยับตามฝนเลย แม้ฝนจะตกหนักจริงก็ตาม

## อัปเดต 2026-07-31 (รอบ 2) — ผู้ใช้ส่งไฟล์ wide_log จริงมาให้ ยืนยัน/แก้ข้อสมมติฐานเดิมแล้ว

ผู้ใช้อัปโหลด `Telemetry_Mae_Na_Rua - wide_log (1).csv` (raw log จริง, 2632 แถว) ตรวจค่าที่ 07:00 ตรงๆ:

```
2026-07-29 07:00:00  RES002_water_level = 488.202
2026-07-30 07:00:00  RES002_water_level = 488.202   <- เท่ากันเป๊ะ
```

**ข้อสมมติฐาน "sensor ค้าง/ข้อมูลซ้ำ" ผิด — นี่คือค่าจริงจาก 2 รอบ poll คนละวันที่บังเอิญเท่ากันพอดี
(3 ตำแหน่งทศนิยม) ไม่ใช่บั๊ก data gap** เช็คข้อมูลรอบ 06:00-07:40 ของวันที่ 30 พบว่าฝนตกจริงและระดับน้ำ
ขยับขึ้นจริงในช่วงเช้า (488.131 ตอน 01:10 → 488.209 ตอน 07:10, +0.08 ม.) แค่บังเอิญจุด 07:00 พอดีของ
สองวันตรงกัน

**สิ่งที่พบเพิ่มที่สำคัญกว่าเดิม — ดูข้อมูลทั้งวันที่ 30 ก.ค.:**

```
01:10  488.131   (ก่อนฝน)
02:50  488.163   ฝนเริ่มตก (rain1h สูงสุด 15.2 มม.)
07:10  488.209   จุดสูงสุดช่วงเช้า (+0.08 ม. จากฝน)
13:50  488.263   จุดสูงสุดของทั้งวัน (+0.13 ม. จาก 01:10)
23:30  488.163   ลดกลับมาใกล้จุดเริ่มต้น (release ระบายออกตลอดวัน)
```

**ระดับน้ำขึ้นจริงจากฝน (+0.13 ม. ที่จุดสูงสุด) แต่ release ที่เปิดค้าง (9,446 m3/วัน) ระบายออกจนระดับ
ไหลกลับมาใกล้จุดเริ่มต้นก่อนถึง 07:00 ของวันถัดไป** ทำให้สูตรที่คำนวณ ΔStorage จากจุด "07:00 ถึง 07:00"
วันเดียว (จุดเดียว ไม่ใช่ช่วง) จับสัญญาณฝนที่เกิดขึ้นจริงระหว่างวันไม่ได้เลย — inflow ที่คำนวณได้จึงติด 0
ทั้งที่มีฝนและมีระดับน้ำขึ้นจริงเกิดขึ้นแล้วในช่วงกลางวัน

## ข้อสรุปที่แก้ไขแล้ว

สาเหตุคือ **2 ปัจจัยรวมกัน** ทั้งคู่ยืนยันจากข้อมูลจริงแล้ว ไม่ใช่การเดา:
1. Release คงที่ 9,446 m3/วัน เปิดค้างมาตั้งแต่ปลาย มิ.ย. มากกว่าฝนที่เติมเข้ามาสุทธิเกือบทุกวัน
2. **วิธีคำนวณ ΔStorage แบบจุดเดียว 07:00-ต่อ-07:00 ไม่จับสัญญาณ intraday** — วันที่มีฝนตกและระดับน้ำขึ้น
   จริงในช่วงเช้า/บ่าย แต่ release ระบายจนกลับมาใกล้จุดเดิมก่อนถึงรอบวัดถัดไป จะถูกนับเป็น "ไม่มี inflow"
   ทั้งที่มีจริง — เป็นข้อจำกัดเชิงวิธีวัด ไม่ใช่บั๊กโค้ด
